# 效能與安全

## 批次映射

映射耗時會隨筆數、可填欄位數，以及選取的請求主體資料量增加。映射本身不會存取資料庫或網路。量測整個操作時，也請計入 Model 建構、cast、mutator 及資料庫寫入的成本。

處理大量資料時，請用實際的 Model 和具代表性的輸入做量測。分批處理並在每批結束後釋放結果，可減少記憶體用量。

## 請求資料與授權

- 一般寫入作業可使用已驗證的 Form Request，或應用程式準備好的陣列。
- `fromRequestInput()` 會檢查所選值的結構。操作授權、日期格式、欄位長度與允許的範圍等規則由應用程式處理。
- 請在解析前限制請求主體大小。套件未設定大小或巢狀深度上限，請在映射前限制要選取的資料，包含中介層或 Form Request 加入的欄位。
- 使用 `merge()`、`setId()` 或 `setUuid()` 時，只傳入應用程式已授權的屬性名稱和值。這些方法可寫入可填清單外的欄位。
- 映射後的屬性可能包含機密或個人資料。只回傳、記錄或儲存該操作所需的值。
